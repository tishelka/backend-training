# Как сдавать упражнения

Каждый студент работает **в своём fork**, потому что оба backend-разработчика будут менять одни и те же файлы. В общем репозитории оставляем стартовую заготовку и уроки. Если руководитель попросил общий PR — уточните целевую ветку.

1. На GitHub нажмите **Fork** и склонируйте адрес **своего** fork.
2. Перед заданием обновите `master` из исходного репозитория (или синхронизируйте fork кнопкой Sync fork). Не делайте это при незакоммиченных правках.
3. Создайте ветку: `git switch -c exercise/03-validation`.
4. Выполните задание, проверьте `python -m pytest -q` и `python -m ruff check .`.
5. `git add .` → `git commit -m "Add validation for activities"` → `git push -u origin exercise/03-validation`.
6. Создайте Pull Request **в master вашего fork** и отправьте ссылку руководителю. Другой вариант — согласованный PR в основной учебный репозиторий.

В PR напишите: что реализовали, какие маршруты проверили в Swagger, какой тест запустили, что было трудным. Нельзя отправлять `.env`, секреты, пароли и личные данные.

**Важно:** после первого урока есть два подхода. Либо вы **наращиваете один и тот же учебный API** от урока к уроку (проще), либо создаёте отдельную ветку от общего старта для каждого урока (сложнее; часть результатов придётся переносить). Для новичков советую **наращивать проект последовательно в своём fork и фиксировать каждый урок коммитом**, а PR открывать на отдельный согласованный checkpoint.

# Финальное задание. Мини-backend без подсматривания

Время собрать свою «стену» из всех кирпичиков. Никакой новой незнакомой технологии здесь нет.

## Что нужно сделать

**Сервис «Каталог идей»** на FastAPI + Pydantic + PostgreSQL + SQLAlchemy + Alembic.

API должно позволять создавать идеи, получать список, получать идею по ID, редактировать и удалять. Добавьте фильтры по категории и максимальному бюджету, сортировку и `limit`. Документируйте всё в **Swagger UI**, чтобы другой студент смог проверить без вашего участия.

## Минимальные требования

- [ ] API запускается локально.
- [ ] `/docs` показывает все операции с понятными названиями.
- [ ] Запросы проходят через Pydantic и дают 422 при ошибках.
- [ ] Данные действительно лежат в PostgreSQL и переживают рестарт API.
- [ ] SQLAlchemy-модели и сессии организованы без глобальной открытой Session.
- [ ] Схема создаётся и обновляется через Alembic.
- [ ] Нет явных секретов в исходниках.
- [ ] Есть тесты на успешные и ошибочные запросы, отдельная тестовая БД.
- [ ] `pytest` и `ruff` работают.
- [ ] В PR объяснено, как воспроизвести запуск.

## Дополнительный уровень (по желанию)

Избранное для **одного общего учебного профиля**, как в MVP: GET/PUT/DELETE, без дублей при повторном PUT. Затем отдельный `seed`, который загружает несколько занятий повторно без дубликатов.

## Проверка руководителем

Попросите напарника открыть ваш Swagger и **самостоятельно** проверить три сценария, не читая исходники. Если ему пришлось угадывать формат запроса, улучшите документацию.
